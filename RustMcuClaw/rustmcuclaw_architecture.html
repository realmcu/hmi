1. 项目总览

RustMcuClaw 是一个以 Rust 编写业务核、运行在 RTL8783G + AmebaZ2+ 双芯架构上的 AI 智能体手表。MCU 负责 UI、控制流、文件系统与定时任务，Z2Plus 作为无线协处理器承担 Wi-Fi/HTTPS/WebSocket 等所有网络业务。

设计目标

  • 内存安全：业务逻辑用 Rust，仅在 FFI/分配器/C 字符串处用 unsafe
  • 双芯解耦：MCU 不接触任何 TCP/TLS 栈，Z2Plus 通过 AT 命令受控
  • 云端 LLM 可插拔：OpenAI / Kimi / GitHub Models / OpenAI-Compatible
  • 持久化：人设、总结记忆、任务全部落 SD 卡 FatFS
  • 主动交互：Feishu wss 长连接推送 → 直接进入 LLM 通道

关键组件

  • MCU Zephyr 多线程 + Rust 静态库
  • Z2Plus AT 固件（ATPN/ATWT/ATKM/ATEP/ATFS/ATSD）
  • LLM rustmcuclaw-mcu crate 生成 OpenAI 兼容 JSON
  • UART uart2 CLI · uart3 ↔ Z2Plus AT 通道
  • UI SH8601Z QSPI LCD + CHSC6417 触摸 + GNU Unifont
  • Memory PSRAM bump allocator + FatFS on SD

★ 智能体闭环（用户输入 · 提示词 · ToolCall · Loop · 文件）

RustMcuClaw 的“大脑”是一段标准的 Agent 主循环：把用户输入与人设/记忆/任务一起拼成提示词，调用 LLM；若响应里带工具调用就在本地执行后回填，最多迭代 max_tool_loops 次；产出最终回复后异步生成不超过 50 字的总结并落盘。

提示词组装顺序

  1. soul.md — 助手核心人格
  2. role.md — 行为/边界约束
  3. user.md — 用户画像
  4. 近 N 条 summary — 长期记忆
  5. 最近 history_limit 轮对话
  6. 当前用户输入

Tool 能力

  • task.add / list / done — 周期 ≥ 10 min
  • fs.read / write — 仅限 /SD:/RustMcuClaw
  • time.now — wall_clock_base + uptime
  • feishu.reply — 走 ATFS 通道回消息
  • 调用结果以 tool 角色回填 messages[]

3. MCU 侧 (RTL87x3G) 软件架构

MCU 上运行 Zephyr RTOS。所有“能阻塞”的工作各自占一根线程，互不抢占主聊天通路。Rust 库通过 extern "C" 暴露的几个入口函数被多线程并发调用，并自带 k_mutex 串行化。

设计取舍

  • ATKM 把 Kimi 鉴权放在 Z2 端，MCU 只传 prompt → 显著减小 MCU 传输/内存负担
  • 通用 HTTPS POST 作为兜底：Rust 生成的 OpenAI-Compatible JSON 透传给 Z2
  • 飞书 URC 用文本标记块包裹，避免分片误解析
  • 失败时返回 ret=X http=Y，MCU 据此区分本地/网络/服务错误

5. UART 桥（MCU ↔ Z2Plus）

两条 UART 各司其职：uart2 暴露给 PC 终端做调试与用户对话；uart3 是 MCU 与 Z2Plus 之间的同步 AT + 异步 URC 双向通道。

uart2 (CLI / Console)

  • IRQ 驱动 + 2048 字节 msgq
  • 支持 \r/\n 行结束，自动丢弃空行
  • 可选本地回显（CLI_LOCAL_ECHO）

uart3 (Z2Plus AT)

  • 同样 IRQ + msgq，专用于和 Z2 通信
  • 大 JSON 分片传输：每 1024 B 节流 30 ms，避免 Z2 端溢出
  • JSON 解析机：在 uart_read_json_body 里逐字符跟踪深度/转义
  • z2_uart_lock 保证 AT 命令-应答原子配对

  • ret<0 本地 / Z2 错（参数 / WiFi 未连）
  • http≠200 远端错（鉴权 / 限流），body 仍打印
  • JSON 解析失败 进入 fallback，本轮回复降级文本
  • timeout 190 s 给 LLM 留足思考时间

7. 飞书 (Feishu) WebSocket 长连接

为了实现“被动唤醒”，Z2Plus 维持一个到飞书开放平台的 wss 长连接；任何飞书事件都被打包成文本块 URC 推到 uart3，再由 MCU 的 z2_urc 线程重组、转交 Rust，自动进入 LLM 通道并把回答推回飞书。

Z2 拿到 app_access_token 并建立 wss Z2->>FS: TLS + WebSocket Upgrade FS-->>Z2: 101 Switching Protocols loop 长连接保持 FS-->>Z2: 文本帧 (message / card / mention) Z2->>U3: 写出 [FSEV-BEGIN]\nheader…\nbody (JSON)\n[FSEV-END] U3->>URC: 字节进 z2_uart_rx_msgq URC->>URC: 找到 BEGIN/END,
把 12 KB fsev_buf 填满 URC->>RUST: rustmcuclaw_mcu_handle_feishu_event(buf,len) RUST->>RUST: 解析 sender / chat_id / text RUST->>RUST: 触发一次普通 LLM round RUST->>U3: HTTPS POST → Feishu reply U3->>FS: 通过 ATFS 通道回消息 RUST->>U2: 同步在本地 LCD 显示 end

URC 文本协议

\r\n[FSEV-BEGIN]\r\n
type: message_received\r\n
chat_id: oc_xxx\r\n
\r\n
{"sender":"...","text":"早上好"}\r\n
[FSEV-END]\r\n
  • 独立优先级线程，避免与 CLI 抢锁导致回复饿死
  • FSEV_BUF_MAX = 12 KB，超大事件被截断告警

双通道融合

  • 飞书事件和 CLI 输入都汇入同一个 app::handle_line
  • 共享同一份记忆 / soul / role / tasks
  • LCD 标题颜色用 DISPLAY_COL_SYSTEM 区分推送来源

8. 内存与 PSRAM 布局

MCU 的 SRAM 紧张，所有大缓冲与 Rust 堆都搬到 4 MB PSRAM。Rust 用一个简单的 bump allocator 适配 no_std + alloc，并在堆水位过高时主动重新初始化以避免长跑碎片化。

Rust allocator

  • rustmcuclaw_mcu_init() 接收 (base, size)
  • 实现 GlobalAlloc：bump + free-list 兜底
  • 堆水位 70% 时，claw_poll 会在空闲期触发 reinit
  • 所有大 String / Vec / serde JSON buffer 都落在这里

SD 卡数据目录

  • 挂载点 /SD:，FatFS 直接走 DISK_ACCESS
  • 路径形式与 PC 版完全一致，便于离线编辑
  • 首次启动写入默认 rmcc.toml
  • Unifont 二进制由 tools/gen_unifont_bin.py 离线生成
